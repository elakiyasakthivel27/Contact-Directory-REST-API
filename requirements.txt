# Contact Directory REST API — Debugging & Enhancement

## Project Overview

This project is part of the Vision Orbit Innovations Task 2 REST API Debugging & Enhancement Challenge.

The application is a Contact Directory REST API developed using **Python, FastAPI, and Pydantic**. It supports creating, retrieving, filtering, updating, and deleting contact records.

The objective was to identify and fix defects in the existing application, implement input validation, improve error handling, and verify functionality through automated tests.

## Technologies Used

- Python 3.12
- FastAPI
- Pydantic
- Uvicorn
- Pytest
- HTTPX

## API Endpoints

| Method | Endpoint | Description | Success Status |
|---|---|---|---|
| GET | `/` | Check API status | 200 |
| GET | `/contacts` | Retrieve all contacts | 200 |
| GET | `/contacts?email=...` | Filter contacts by email | 200 |
| GET | `/contacts/{contact_id}` | Retrieve a specific contact | 200 |
| POST | `/contacts` | Create a new contact | 201 |
| PATCH | `/contacts/{contact_id}` | Update an existing contact | 200 |
| DELETE | `/contacts/{contact_id}` | Delete a contact | 200 |

## Bugs Identified and Fixed

### 1. Incorrect Email Filtering

**Issue:** The email filter returned contacts whose email addresses did not match the requested email.

**Fix:** Corrected the comparison logic to return matching contacts.

### 2. Duplicate Email Handling

**Issue:** The API allowed multiple contacts with the same email address.

**Fix:** Added duplicate email checks during contact creation and email updates. Email comparisons are case-insensitive.

**Error Response:** `409 Conflict`

### 3. Missing Input Validation

**Issue:** Invalid names, email addresses, and phone numbers could be submitted.

**Fix:** Added Pydantic validation rules:

- Name: 2–50 characters
- Email: Valid email format
- Phone: Exactly 10 numeric digits

**Error Response:** `422 Unprocessable Entity`

### 4. PATCH Validation and Null Handling

**Issue:** Contact updates required improved validation and protection against invalid values.

**Fix:** Added validation for update requests and prevented explicitly setting contact fields to `null`.

**Error Response:** `422 Unprocessable Entity`

### 5. Incorrect DELETE Error Handling

**Issue:** Deleting a nonexistent contact returned a success response.

**Fix:** Added an existence check before deletion.

**Error Response:** `404 Not Found`

## Assumptions and Limitations

- Contact records are stored in an in-memory Python dictionary.
- Data is not persisted after the application restarts.
- Email addresses must be unique across contacts.
- Phone numbers must contain exactly 10 digits.
- The project does not include authentication or a frontend, as these were outside the assessment scope.
